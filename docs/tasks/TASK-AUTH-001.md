# TASK-AUTH-001 微信登录与用户态接入

## 任务 ID

`TASK-AUTH-001`

## 背景

MVP 要求核心功能需要登录，登录前展示协议勾选。当前后端菜谱接口已经通过 CloudBase 获取可信微信身份并映射用户，但小程序端尚未形成完整登录态、未登录拦截和用户信息展示。

## 目标

建立微信登录与用户态闭环，让核心页面能够识别未登录状态、完成登录、保存当前用户状态，并为后续合规页面提供基础。

## 范围

### 包含

- 小程序端登录入口和登录态检查。
- 登录前协议勾选。
- 获取当前用户基础信息。
- 未登录访问核心功能时引导登录。
- 退出登录。
- 服务端用户身份映射与当前用户接口或等价 action。
- 登录失败和登录失效处理。

### 不包含

- 不获取手机号。
- 不做复杂账号体系。
- 不做自动化账号注销清理。
- 不把 AppSecret 放到小程序端。

## 实现要求

- 写接口必须依赖服务端可信身份或登录态。
- 小程序端不得包含 `WECHAT_APP_SECRET`。
- 未登录状态不能调用需要登录的写接口。
- 登录态失效时统一提示并引导重新登录。
- 登录前必须能查看并勾选协议。

## 前端设计保护

涉及 profile 和可能的登录入口，允许新增页面/状态，但不得破坏已完成核心页面设计。

- 是否改 WXML：是，限登录/profile/未登录状态
- 是否改 WXSS：是，限登录/profile/未登录状态
- 是否改组件结构：否，除非新增登录组件
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：我的页、核心 Tab 未登录态
  - 弹窗：协议勾选或登录确认
  - 手势：不涉及
  - 空态/加载态/失败态：登录中、登录失败、登录失效

## API/数据变更

- 可新增或确认：
  - 当前用户信息 action/API。
  - 登出 action/API。
  - 用户协议版本记录字段。
- 不得在小程序端保存敏感服务端密钥。

## 验收标准

- [ ] 首次进入核心功能时可引导登录。
- [ ] 登录前可勾选协议。
- [ ] 微信快捷登录成功后进入主功能。
- [ ] 我的页可展示用户信息。
- [ ] 可退出登录。
- [ ] 登录失效时有明确处理。
- [ ] 服务端写接口具备用户隔离。

## 测试要求

- [ ] 单元测试：登录态 store/request 拦截器逻辑，如有。
- [ ] 接口测试：当前用户、登出、未登录错误。
- [ ] 页面冒烟：首次登录、退出、重新进入。
- [ ] 回归范围：菜谱、计划、菜篮未登录态。

## 风险

- 微信登录链路依赖小程序和 CloudBase/后端真实环境。
- 协议文案和版本需 PM 确认。
