# TASK-RECIPE-SYSTEM-TAGS-001 菜谱系统标签

## 目标

将可解释的系统标签写入每道菜谱，供规则周计划稳定使用，且不增加用户手动打标负担。

## 范围

### 包含

- `recipes.system_tags` 持久化字段及历史菜谱回填。
- 菜谱创建、编辑时由服务端触发器自动重建标签。
- 标签值、来源、可信度和版本号。
- 周计划候选读取标签，缺失时兼容旧关键词规则。
- 迁移、单元测试和数据库验证用例。

### 不包含

- 用户查看、编辑或筛选标签的页面。
- AI 推断、营养分析、忌口自动识别。
- 改动现有小程序页面、组件或视觉样式。

## 相关上下文

- 模块 spec：`docs/specs/recipe.md`、`docs/specs/plan.md`
- 数据模型：`recipes.system_tags`
- API：既有 `recipes.create`、`recipes.update`、`plans.week.generate`，不新增客户端接口。

## 实现要求

- 标签只来源于菜名、食材、步骤、分类和耗时；每项保存 `value`、`source`、`confidence`。
- 「西红柿」统一归为 `tomato`，并标注 `title_alias`。
- 标签由服务端生成，客户端不能覆盖。
- 计划和菜篮既有快照不回写；标签只影响之后的周计划候选选择。
- 用户隔离保持由现有 owner-scoped RPC 保证。

## 前端设计保护

- 是否改 WXML：否
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 视觉回归范围：不涉及

## 验收标准

- [x] 新建和编辑菜谱自动持久化系统标签。
- [x] 历史菜谱在迁移中补齐标签。
- [x] 标签含来源、可信度、版本号，且不接 AI。
- [x] 周计划优先使用持久化标签，缺失时仍可生成。
- [x] 历史计划和菜篮快照不被标签回填影响。

## 测试要求

- [x] 单元测试覆盖版本化标签校验与周计划标签消费。
- [x] 数据库集成用例覆盖「西红柿炒鸡蛋」的别名、蛋白质和耗时标签。
- [x] 回归：服务端构建及单元测试。

## 风险

- 首版是词典规则，不等同于营养学或 AI 判断；未识别的菜谱会保留低可信度默认标签并继续使用兼容规则生成。
