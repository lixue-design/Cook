# TASK-OBSERVABILITY-001 基础日志与错误可诊断性

## 任务 ID

`TASK-OBSERVABILITY-001`

## 背景

MVP 内测和提审前需要能定位关键失败，例如登录失败、保存失败、计划生成 warning、菜篮同步失败。当前任务卡强调错误态展示，但还需要最小日志和诊断信息，帮助研发判断是配置、网络、鉴权还是业务校验问题。

## 目标

建立基础日志和错误诊断口径，让关键接口和页面失败可追踪、可复现、可汇报。

## 范围

### 包含

- 服务端关键 action/API 记录最小结构化日志。
- 关键错误返回包含稳定错误码和用户可读 message。
- 小程序 service 层保留必要错误上下文，页面展示用户可读提示。
- 计划生成 warnings 和菜篮同步 warnings 可记录和展示。
- 文档说明内测时如何收集失败信息。

### 不包含

- 不接入商业 APM 或复杂埋点平台。
- 不采集敏感个人信息、密钥、完整图片内容。
- 不做增长分析埋点。
- 不改变业务结果。

## 实现要求

- 日志不得包含 AppSecret、token、数据库连接串或用户隐私明文。
- 错误码应稳定，便于测试断言和问题归类。
- 前端展示文案要面向用户，日志上下文面向研发。
- 对外错误不能泄露数据库 SQL、堆栈或内部路径。

## 前端设计保护

- 是否改 WXML：否，除非补错误提示入口
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：核心页面错误提示
  - 弹窗：保存失败、同步失败、登录失败
  - 手势：不涉及
  - 空态/加载态/失败态：失败态提示

## API/数据变更

- 可新增统一错误结构或错误码枚举。
- 如错误结构变化，必须同步 API 契约。

## 验收标准

- [ ] 登录、菜谱保存、计划生成、菜篮同步失败有稳定错误码。
- [ ] 服务端日志不输出密钥和敏感隐私。
- [ ] 前端页面展示用户可读错误。
- [ ] 研发可根据错误码和时间定位失败模块。
- [ ] warnings 不被当成致命错误。

## 测试要求

- [ ] 单元测试：错误码映射或日志脱敏，如有。
- [ ] 接口测试：典型错误态返回稳定结构。
- [ ] 手动检查：日志不含密钥、token、连接串。
- [ ] 回归范围：登录、菜谱保存、计划生成、菜篮同步。

## 风险

- 不接入外部日志平台时，线上诊断能力有限；MVP 只要求最小可诊断。
