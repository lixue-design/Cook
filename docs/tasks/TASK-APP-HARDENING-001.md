# TASK-APP-HARDENING-001 全局空态错误态与未登录态回归

## 任务 ID

`TASK-APP-HARDENING-001`

## 背景

MVP 验收清单要求菜谱、日计划、周计划、菜篮都有明确空态，网络失败有提示，保存失败不丢表单，未登录状态处理合理。各模块真实化完成后，需要一次横向回归，避免局部任务完成但整体体验断裂。

## 目标

统一核心页面加载态、空态、失败态和未登录态，完成小程序主路径体验硬化。

## 范围

### 包含

- 菜谱列表、详情、创建/编辑的空态和失败态检查。
- 日计划、周计划的空态、生成失败、warnings 展示检查。
- 菜篮空态、同步失败、保存失败检查。
- 我的页和核心 Tab 未登录态检查。
- 网络失败、登录失效、接口错误的提示口径统一。
- 危险操作确认：删除、覆盖周计划、注销申请、退出登录。

### 不包含

- 不重写页面视觉。
- 不新增复杂全局状态管理框架。
- 不引入第三方 UI 库。
- 不改变业务规则。

## 实现要求

- 优先复用现有组件和页面样式。
- 不为统一状态而重写 WXML/WXSS。
- 错误提示要能区分用户可处理错误和系统错误。
- 登录失效必须引导重新登录，不应静默失败。
- 保存失败场景不得清空用户输入。

## 前端设计保护

- 是否改 WXML：是，限必要状态补齐
- 是否改 WXSS：是，限状态样式小修
- 是否改组件结构：否，除非复用现有状态组件
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：菜谱列表、详情、创建/编辑、计划、菜篮、我的
  - 弹窗：删除确认、覆盖确认、退出登录、注销申请
  - 手势：滑动删除、拖拽、周切换、弹窗开合
  - 空态/加载态/失败态：全部核心页面

## API/数据变更

- 不要求新增接口。
- 可在 service 层统一错误映射；如错误结构变化需同步 API 契约。

## 验收标准

- [ ] 菜谱列表空态明确。
- [ ] 日计划空态明确。
- [ ] 周计划空态明确。
- [ ] 菜篮空态明确。
- [ ] 网络失败有提示。
- [ ] 登录失效有引导。
- [ ] 保存失败不丢表单内容。
- [ ] 删除和覆盖类操作有确认。
- [ ] 核心页面视觉和手势未被破坏。

## 测试要求

- [ ] 页面冒烟：菜谱、计划、菜篮、我的所有空态和失败态。
- [ ] 手动回归：滑动删除、拖拽、周切换、半屏弹窗。
- [ ] 接口错误模拟：未登录、网络失败、保存失败。
- [ ] 回归范围：小程序四个 Tab 和菜谱创建/详情。

## 风险

- 微信开发者工具外无法完全自动化验证手势和视觉，需要手动记录结果。
