# TASK-QA-MVP-001 MVP 全链路验收与冒烟脚本

## 任务 ID

`TASK-QA-MVP-001`

## 背景

各模块任务完成后，需要按 `docs/checklists/mvp-acceptance.md` 做一次全链路验收。否则单个任务通过并不代表用户闭环可用，尤其是登录、菜谱、计划、菜篮和合规之间的串联。

## 目标

跑完 MVP 验收清单和提审前冒烟路径，形成可复查的验收记录。

## 范围

### 包含

- 对照 MVP 验收清单逐项检查。
- 执行提审前冒烟路径。
- 记录通过、失败、阻塞和替代检查结果。
- 检查 PR checklist 中的范围、快照、鉴权、错误态和测试项。
- 汇总剩余 P0/P1 风险。

### 不包含

- 不实现新功能。
- 不临时放宽 MVP 验收标准。
- 不处理法务最终文案确认，除非已有明确文案。

## 相关上下文

- MVP 验收：`docs/checklists/mvp-acceptance.md`
- PR checklist：`docs/reviews/pr-review-checklist.md`
- 本地验证：`docs/harness/local-development-and-verification.md`
- 全量任务索引：`docs/tasks/README.md`

## 实现要求

- 验收记录必须包含运行环境和日期。
- 无法运行的测试必须说明原因、替代检查和剩余风险。
- 冒烟路径至少覆盖：

```text
登录
-> 新建菜谱
-> 查看详情
-> 编辑菜谱
-> 生成周计划
-> 添加/移除某日餐段菜谱
-> 同步菜篮
-> 勾选采购项
-> 查看协议
-> 退出登录
```

- 若发现任务卡遗漏，应补任务卡或在 README 队列中新增后续项。

## 前端设计保护

不主动改页面；如发现视觉或交互回归，记录为缺陷或新增修复任务。

- 是否改 WXML：否
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：不涉及
- 视觉回归范围：
  - 页面：四个 Tab、菜谱详情、菜谱创建/编辑、协议/注销
  - 弹窗：半屏弹窗、删除确认、覆盖确认、退出确认
  - 手势：滑动删除、拖拽、周切换、弹窗开合
  - 空态/加载态/失败态：全量核心页面

## API/数据变更

不涉及。

## 验收标准

- [ ] MVP 验收清单逐项有结果。
- [ ] 提审前冒烟路径完成。
- [ ] 后端构建和相关测试有运行记录或替代说明。
- [ ] 小程序页面冒烟有结果记录。
- [ ] P0/P1 风险被列出并关联任务。

## 测试要求

- [ ] 单元测试：运行相关模块单测。
- [ ] 接口测试：运行可用接口测试。
- [ ] 页面冒烟：运行全链路手动冒烟。
- [ ] 回归范围：登录、菜谱、计划、菜篮、我的、协议、注销。

## 风险

- 微信开发者工具、CloudBase、数据库或真实小程序环境缺失时，部分验收只能做替代检查。

## 完成汇报模板

```text
完成：
- 跑完 MVP 验收清单和提审前冒烟路径

验证：
- 记录测试命令、页面冒烟和未运行项

风险/后续：
- 汇总 P0/P1 风险和阻塞项
```
