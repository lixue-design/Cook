# TASK-PLAN-RULE-BALANCE-001

## 任务 ID

`TASK-PLAN-RULE-BALANCE-001`

## 背景

Full PRD 要求计划生成综合用户饮食习惯、三餐差异、主食/蛋白质/蔬菜轻量均衡。现有周计划生成已具备基础早餐、忌口和食材角色识别，但尚未充分使用午晚餐偏好、常用主食和工作日/周末耗时。

## 目标

增强 rules 周计划生成器，让计划结果体现三餐差异、用户主食偏好和耗时限制。

## 范围

### 包含

- 扩展 `WeekPlanPreferences` 使用字段。
- 午餐偏好快手/便当时优先一餐完成或快手菜。
- 晚餐偏好家庭/均衡时优先蛋白质 + 蔬菜 + 主食组合。
- 常用主食影响主食选择和内置主食补位。
- 工作日/周末可接受耗时影响候选排序和 warning。
- 补充周计划生成单测。

### 不包含

- AI 自动计划。
- 复杂营养素计算。
- 月计划批量生成。
- 前端偏好设置页面改造。

## 相关上下文

- 模块 spec：`docs/specs/rule-generation-engine.md`、`docs/specs/plan-advanced.md`、`docs/specs/plan.md`
- API：`plans.week.generate`
- 页面：不涉及
- 数据模型：复用 `plan_preferences` 和现有日级计划快照写入

## 实现要求

- 首版仍为 provider=`rules`。
- 保持日计划为唯一事实源，周计划生成仍写入日级计划快照。
- 菜谱不足时返回稳定 warning，不阻塞生成。
- 不引入黑盒评分或不可解释逻辑。
- 不修改 WXML/WXSS。

## Full PRD 限制

- Provider 策略：仅使用 rules provider；不接 AI provider，不提交模型密钥。
- 前端样式保护：不修改小程序页面、组件、布局、手势、自定义 Tab 或半屏弹窗。
- 数据事实来源：用户习惯来自 `plan_preferences`；生成结果通过 `cook_plan_generate_week` 写入日级事实。
- 快照规则：生成仍写入菜谱快照，后续菜谱编辑不污染计划。
- 用户隔离：偏好和候选菜谱均通过服务端可信 owner 读取。
- 不可做事项：不做复杂营养分析、不做月计划、不写菜篮、不接 AI。

## 前端设计保护
