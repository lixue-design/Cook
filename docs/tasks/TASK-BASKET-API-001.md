# TASK-BASKET-API-001 周菜篮数据模型与接口

## 任务 ID

`TASK-BASKET-API-001`

## 背景

当前菜篮页已有分组、勾选、滑动删除、长按拖拽、新增食材交互，但数据仍来自 mock/globalData。MVP 要求周菜篮按自然周持久化，支持从计划同步、勾选、手动新增和删除，并保留手动项。

## 目标

实现周菜篮真实数据模型和服务端接口，为前端菜篮页提供持久化数据源。

## 范围

### 包含

- 新增 `shopping_baskets` 和 `shopping_basket_items` 等数据模型及回滚。
- 获取某周菜篮。
- 从周计划同步菜篮。
- 手动新增菜篮项。
- 修改菜篮项或勾选状态。
- 删除菜篮项。
- 批量勾选或取消。
- 所有数据按用户隔离。

### 不包含

- 不实现复杂单位换算。
- 不做多人共享采购。
- 不做价格估算或库存管理。
- 不重写菜篮页 UI。

## 实现要求

- MVP 同步模式默认 `replace_plan_items`：
  - 删除旧计划来源项。
  - 保留手动项。
  - 从当前周计划快照重新汇总。
- 手动新增项 `source = manual`，计划项 `source = plan`。
- 勾选状态必须持久化。
- 同步失败不能清空现有菜篮。
- 接口错误要可被前端展示。

## 前端设计保护

后端为主；前端接入留给 `TASK-BASKET-FRONTEND-001`。

- 是否改 WXML：否
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：菜篮页
  - 弹窗：新增食材
  - 手势：勾选后重排、滑动删除、长按拖拽
  - 空态/加载态/失败态：无计划、同步失败、保存失败

## API/数据变更

- 新增菜篮数据库迁移和回滚。
- 新增服务端 action/API，建议覆盖：

  - 从计划同步。
  - 新增手动项。
  - 更新项/勾选。
  - 删除项。
  - 批量勾选。
