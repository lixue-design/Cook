# TASK-FULL-PRD-SMOKE-001

## 任务 ID

`TASK-FULL-PRD-SMOKE-001`

## 背景

Full PRD 队列要求在功能切片完成后执行全量主链路冒烟，覆盖规则生成、菜品图库、日/周/月计划、菜篮、注销和协议版本。该冒烟必须在真实或 staging 环境中连续执行，不能用本地 mock 代替真实验收。

## 目标

使用同一 staging 账号、真实 CloudBase/云函数/数据库/存储桶和微信开发者工具或真机，完成 Full PRD 主链路冒烟并记录证据。

## 当前状态

`Blocked`

## 阻塞原因

- `TASK-ACCOUNT-CANCEL-EXECUTE-001` 仍为 `Blocked`，管理端 dry-run 和正式注销处理无法冒烟。
- 缺少已确认的真实 CloudBase 环境、云函数名称、数据库迁移应用记录和存储桶配置。
- 缺少微信开发者工具或真机连续主链路冒烟环境证据。
- 缺少产品/法务确认的协议与隐私最终文案、注销 SLA 和数据处理范围。
- 当前 Codex 环境无法替代真实小程序登录授权、上传、云函数、存储桶和真机手势验收。

## 范围

### 包含

- 登录并确认协议。
- 规则 provider 链接/图片/文字生成菜谱草稿。
- 保存、编辑菜谱并验证图库匹配/手动封面优先级。
- 生成周计划、历史复刻、选择性同步菜篮。
- 查看月历、批量填充/清空/替换、月度统计、模板保存和应用。
- 提交注销申请、管理端 dry-run 与处理。
- 协议版本更新后重新确认。
- 记录加载态、空态、失败态、未登录态、手势和视觉回归结果。

### 不包含

- 用 mock 冒充真实环境验收。
- 在缺少法务/安全批准时执行真实注销删除/匿名化。
- 未授权访问生产用户数据或记录敏感截图。

## 实现要求

- 必须使用 remote/staging 环境，不得使用 mock 结论替代真实验收。
- 必须记录 API 模式、测试账号脱敏标识、环境版本、操作步骤、结果和证据。
- 发现 P0/P1 缺陷时，使用 `docs/reviews/defect-report-template.md` 记录并阻塞发布。
- 涉及注销处理必须等待 dry-run、管理员鉴权、二次确认和法务范围确认。

## Full PRD 限制

- Provider 策略：首版生成入口必须使用 `provider=rules`，不得接真实 AI 或提交模型密钥。
- 前端样式保护：冒烟需确认既有页面样式、Tab、半屏弹窗、拖拽/滑动手势未回归。
- 数据事实来源：计划/月计划/菜篮均以服务端事实源和日级计划快照为准。
- 快照规则：计划、菜篮、模板、复刻均需验证快照不被菜谱编辑污染。
- 用户隔离：所有用户数据必须在同一 owner 下验证，且不得访问其他用户数据。
- 不可做事项：不使用 mock 替代真实验收、不执行未批准的注销清理、不记录敏感凭据。
