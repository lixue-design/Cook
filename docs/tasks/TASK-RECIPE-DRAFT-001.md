# TASK-RECIPE-DRAFT-001 新建编辑草稿与表单校验硬化

## 任务 ID

`TASK-RECIPE-DRAFT-001`

## 背景

MVP 要求新建/编辑菜谱时保存失败不丢表单内容，退出未保存需有二次确认，强杀重启恢复可用本地缓存。当前菜谱创建页已有表单体验，但草稿、校验和失败恢复需要作为独立体验闭环验收。

## 目标

让新建/编辑菜谱在保存失败、退出重进、图片上传失败等场景下不丢关键输入，并完成服务端兜底校验。

## 范围

### 包含

- 菜名、耗时、热量、分类、食材、步骤的前端校验。
- 保存失败时保留当前表单状态。
- 新建草稿本地缓存，保存成功后清除。
- 编辑草稿按 `recipeId` 区分。
- 退出未保存二次确认。
- 后端保存接口做最终校验。

### 不包含

- 不做云端草稿同步。
- 不做多人协作编辑。
- 不做 AI 文本生成菜谱。
- 不重写菜谱创建页设计。

## 实现要求

- 草稿 key 建议区分 `recipeDraft:new` 和 `recipeDraft:{recipeId}`。
- 保存成功后必须清除对应草稿，避免旧数据污染下次创建。
- 前端校验只用于体验，服务端仍需拒绝非法入参。
- 表单字段映射不能破坏现有详情页和列表页字段契约。
- 错误提示需要可被用户理解，不暴露服务端敏感信息。

## 前端设计保护

- 是否改 WXML：否，除非补必要错误态或确认弹窗
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：菜谱创建/编辑
  - 弹窗：退出未保存确认、保存失败提示
  - 手势：不涉及
  - 空态/加载态/失败态：保存中、保存失败、草稿恢复

## API/数据变更

- 不要求新增接口。
- 若补服务端校验错误码，需同步 API 契约或状态矩阵。

## 验收标准

- [ ] 菜名为空时阻止保存并提示。
- [ ] 耗时和热量非法时阻止保存并提示。
- [ ] 保存失败后表单内容不丢失。
- [ ] 新建草稿可恢复，保存成功后清除。
- [ ] 编辑草稿不污染其他菜谱或新建表单。
- [ ] 退出未保存有二次确认。

## 测试要求

- [ ] 单元测试：字段校验、草稿 key 或数据转换，如有。
- [ ] 接口测试：非法入参被服务端拒绝。
- [ ] 页面冒烟：新建草稿恢复、编辑草稿隔离、保存失败保留输入。
- [ ] 回归范围：菜谱创建、编辑、详情返回路径。

## 风险

- 小程序本地缓存容量和清理策略需保持简单，避免存储大图片原始数据。
