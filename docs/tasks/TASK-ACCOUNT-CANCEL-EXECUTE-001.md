# TASK-ACCOUNT-CANCEL-EXECUTE-001

## 任务 ID

`TASK-ACCOUNT-CANCEL-EXECUTE-001`

## 背景

Full PRD 要求账号注销支持 dry-run、删除/匿名化、幂等执行和失败重试。当前已完成注销申请状态机与审计基础，但正式处理真实用户数据属于不可逆高风险操作，必须先确认法务、产品、安全和运维门禁。

## 目标

在外部合规门禁确认后，实现注销数据处理任务：先 dry-run 生成清单，再由管理员确认执行删除/匿名化，并写入审计和可重试任务状态。

## 当前状态

`Blocked`

## 阻塞原因

- 缺少产品/法务确认的数据删除与匿名化范围。
- 缺少必须保留的合规日志、审计日志和运营记录边界。
- 缺少执行前备份、回滚或恢复策略。
- 缺少管理员身份复核、二次确认和执行人权限规则。
- 缺少 15 个工作日 SLA、用户完成通知和失败通知规则。

## 范围

### 包含

- `admin.accountCancel.dryRun`：生成将删除/匿名化的数据清单。
- `admin.accountCancel.execute`：在 dry-run 和二次确认后执行处理。
- `admin.accountCancel.logs`：查看执行和状态审计日志。
- 幂等执行和失败重试。
- 注销完成后把申请流转到 `completed` 或失败时流转到 `failed`。

### 不包含

- 未经确认直接物理删除真实用户数据。
- 客户端直接触发最终删除。
- 绕过 dry-run 或管理员确认。
- 删除法律法规要求保留的脱敏日志。

## 实现要求

- 正式执行前必须存在 dry-run 记录。
- 正式执行必须要求管理员鉴权和二次确认。
- 执行任务必须幂等，可重试且可审计。
- 删除/匿名化范围至少覆盖经确认的用户资料、自建菜谱、计划、菜篮和生成任务数据。
- 不得删除必须保留的合规审计记录；保留记录必须脱敏。

## Full PRD 限制

- Provider 策略：不涉及 AI；不触发生成 provider。
- 前端样式保护：不修改小程序 WXML/WXSS、页面布局、手势、自定义 Tab 或半屏弹窗。
- 数据事实来源：注销处理任务状态和审计日志是处理事实源。
- 快照规则：删除/匿名化不得破坏需依法保留的脱敏审计证据。
- 用户隔离：处理范围必须按 owner 精确限定。
- 不可做事项：不在合规门禁缺失时实现真实执行，不允许客户端执行最终删除。
