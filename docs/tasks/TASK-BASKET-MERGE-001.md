# TASK-BASKET-MERGE-001 服务端食材合并规则

## 任务 ID

`TASK-BASKET-MERGE-001`

## 背景

当前 `utils/shopping-list.js` 在小程序端按食材名合并，并把不同用量拼成字符串。这与 MVP 规则不一致。MVP 要求食材合并必须在服务端执行，只合并同名同单位且数字用量可解析的项；同名不同单位和不可解析用量必须分行保留。

## 目标

实现可测试的服务端食材合并函数，并在菜篮同步中使用，确保合并规则符合 spec。

## 范围

### 包含

- 服务端实现食材标准化和合并函数。
- 支持从计划快照中的食材读取 `name`、`amount`、`amountText`、`unit`。
- 同名同单位且数字可解析时求和。
- 同名不同单位分行展示。
- 不可解析用量分行展示并保留原始文本。
- 输出包含来源引用 `source_refs`。
- 单元测试覆盖主要边界。

### 不包含

- 不做斤到克、ml 到杯等复杂单位换算。
- 不用 AI 或黑盒模型做食材归一。
- 不改变前端视觉。

## 实现要求

- 合并 key 为标准化后的 `name + unit`。
- `amount` 必须能解析为数字才参与求和。
- `amountText` 需要保留展示文本。
- 空单位只和空单位合并，不能与其他单位混合。
- 对不可解析值如「少许」「适量」保留原始文本。
- 生成结果要稳定排序，便于测试和页面展示。

## 验收标准

- [ ] `鸡蛋 2 个 + 鸡蛋 3 个` 合并为 `鸡蛋 5 个`。
- [ ] `鸡蛋 2 个 + 鸡蛋 100 g` 分行展示。
- [ ] `盐 少许 + 盐 适量` 分行或保留原始文本，不求和。
- [ ] 手动新增项不参与计划来源替换删除。
- [ ] 合并结果包含来源引用。
- [ ] 规则有单元测试。

## 测试要求

- [ ] 单元测试：同名同单位求和、不同单位分行、不可解析分行、空单位、来源引用。
- [ ] 接口测试：菜篮同步中使用合并函数。
- [ ] 页面冒烟：后续任务覆盖。
- [ ] 回归范围：不影响现有 recipe/plan 测试。

## 风险

- 当前菜谱食材在前端和后端部分仍是文本字段，可能需要在计划快照生成时补结构化解析。
- 解析规则必须简单透明，不要扩展成复杂单位换算。
