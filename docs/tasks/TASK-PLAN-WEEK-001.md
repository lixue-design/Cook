# TASK-PLAN-WEEK-001 周计划生成规则与 warnings

## 任务 ID

`TASK-PLAN-WEEK-001`

## 背景

MVP 要求用户可以一键生成本周计划。当前周计划页展示的是 mock 数据，尚无服务端规则引擎。周计划生成必须可解释、可测试，菜谱不足时允许生成不完整计划并返回 warnings。

## 目标

实现服务端周计划生成能力，基于用户菜谱按规则生成七天三餐计划，并写入计划快照。

## 范围

### 包含

- 新增生成指定自然周计划的接口/action。
- 已有计划时支持覆盖确认参数。
- 生成七天早餐、午餐、晚餐。
- 菜谱不足时返回 warnings。
- 使用 `TASK-PLAN-API-001` 的计划模型和快照机制。
- 单元测试覆盖重复控制、早餐兜底、主食兜底、菜谱不足。

### 不包含

- 不做 AI 生成菜单。
- 不做人群偏好、忌口、人数设置。
- 不做月计划。
- 不做复杂营养计算。

## 实现要求

- 遵循 spec 中的 MVP 规则：
  - 早餐候选最多重复 2 次，至少间隔 2 天。
  - 工作日午/晚餐优先一荤一素一主食或一餐完成菜。
  - 周末每天最多 1 道耗时菜。
  - 菜谱不足时逐步放宽重复规则。
  - 无早餐菜谱使用内置早餐组合。
  - 无主食使用「米饭」补位。
- 每个生成项必须保存快照。
- warnings 要能被前端展示。
- 已有计划且未传覆盖参数时返回明确错误。

## 前端设计保护

后端为主；前端展示 warnings 留给 `TASK-PLAN-FRONTEND-001`。

- 是否改 WXML：否
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：周计划页
  - 弹窗：覆盖确认
  - 手势：周切换、周视图食物块拖拽
  - 空态/加载态/失败态：生成失败、warnings

## API/数据变更

- 新增周计划生成 action/API。
- 返回值包含周计划数据和 `warnings`。
- 如需要新增内置早餐/主食标识，应记录在任务卡或 spec 补充中。

## 验收标准

- [ ] 可生成指定周的七天三餐。
- [ ] 已有计划时不覆盖，除非明确传覆盖参数。
- [ ] 菜谱不足时生成成功并返回 warning。
- [ ] 生成项均保存菜谱快照。
- [ ] 删除原菜谱后，生成计划仍可通过快照展示。
- [ ] 规则引擎有单元测试覆盖。

## 测试要求

- [ ] 单元测试：早餐重复、主食兜底、菜谱不足、周末耗时菜限制。
- [ ] 接口测试：生成、覆盖确认、warnings。
- [ ] 页面冒烟：后续任务覆盖。
- [ ] 回归范围：计划表写入、快照字段。

## 风险

- 规则效果可能不够智能，但 MVP 以可解释和可调整为优先。
- 菜谱缺少结构化标签时，需要使用名称/分类/耗时的弱规则推断。
