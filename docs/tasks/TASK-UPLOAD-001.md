# TASK-UPLOAD-001 菜谱图片上传与压缩兜底

## 任务 ID

`TASK-UPLOAD-001`

## 背景

MVP 要求菜谱封面和步骤图可上传，前端最长边压缩到 1280px，后端限制 5MB，并且图片上传失败不能导致表单内容丢失。现有菜谱 remote 任务覆盖封面上传，但步骤图、压缩限制和失败兜底需要单独验收。

## 目标

让封面图和步骤图上传、压缩、大小限制、失败重试或无图保存成为可验证闭环。

## 范围

### 包含

- 封面图上传接真实能力或明确可无图保存。
- 步骤图上传接真实能力或明确 MVP 降级策略。
- 小程序端图片选择和压缩到最长边 1280px。
- 后端或 Cloud Function 校验格式和 5MB 大小限制。
- 上传失败时保留表单内容，允许重试或无图保存。
- 补充上传错误码和前端提示映射。

### 不包含

- 不做 AI 图片识别生成菜谱。
- 不做图片审核后台。
- 不做多图步骤或视频步骤。
- 不提交真实存储密钥或生产配置。

## 实现要求

- 优先复用现有图片选择区和步骤编辑 UI，不重写页面结构。
- 上传前校验格式和大小，服务端也必须兜底。
- 存储路径不能允许用户引用其他用户资源。
- 上传失败不能清空表单、食材或步骤。
- 若真实上传环境不可用，必须保留无图保存路径并记录风险。

## 前端设计保护

- 是否改 WXML：否，除非补必要失败态
- 是否改 WXSS：否
- 是否改组件结构：否
- 是否保持现有字段契约：是
- 是否优先通过 `services/` 或数据映射接入：是
- 视觉回归范围：
  - 页面：菜谱创建/编辑、菜谱详情
  - 弹窗：图片选择、上传失败提示
  - 手势：不涉及
  - 空态/加载态/失败态：上传中、上传失败、无图保存

## API/数据变更

- 可复用 `covers.upload` action。
- 如新增步骤图上传 action，需同步 `docs/api/status-matrix.md` 或 API 契约。
- 图片字段必须映射到 `coverImageUrl`、`steps[].imageUrl` 或页面现有等价字段。

## 验收标准

- [ ] 可选择并上传菜谱封面图。
- [ ] 可选择并上传步骤图，或明确步骤图 MVP 降级策略。
- [ ] 图片超过限制时有可读提示。
- [ ] 上传失败后表单内容不丢失。
- [ ] 可无图保存菜谱。
- [ ] 图片资源按用户隔离或使用服务端可信存储路径。

## 测试要求

- [ ] 单元测试：图片大小、格式、路径校验，如有。
- [ ] 接口测试：上传成功、超限、非法格式、未登录。
- [ ] 页面冒烟：新建菜谱选择封面/步骤图，上传失败后继续保存。
- [ ] 回归范围：菜谱创建/编辑和详情图片展示。

## 风险

- 微信开发者工具、CloudBase storage 或对象存储环境不可用时，只能做降级和替代检查。
