# PR Review Checklist

每个 PR 合并前至少检查以下内容。

## 1. 范围

- [ ] PR 目标清晰，能对应到任务卡或模块 spec。
- [ ] 没有实现 MVP 之外的能力。
- [ ] 没有把 AI、月计划、运营后台等后置能力混入主任务。
- [ ] 没有无关重构或大范围格式化。

## 2. 业务规则

- [ ] 计划项写入时保存菜谱快照。
- [ ] 菜谱编辑不影响历史计划和已生成菜篮。
- [ ] 菜篮只合并同名同单位且数字用量可解析的食材。
- [ ] 手动菜篮项不会被计划同步删除。
- [ ] 删除菜谱后历史计划仍可展示快照。

## 3. 接口与数据

- [ ] 新接口有鉴权。
- [ ] 新接口有参数校验。
- [ ] 错误返回可被前端展示。
- [ ] 数据表包含必要用户隔离字段。
- [ ] migration 可回滚或有明确说明。
- [ ] 没有提交密钥、token、生产账号。

## 4. 前端体验

- [ ] 页面有加载态。
- [ ] 页面有空态。
- [ ] 页面有失败态。
- [ ] 保存失败不丢用户输入。
- [ ] 删除/覆盖等危险操作有确认。
- [ ] 未登录状态处理合理。
- [ ] 保留现有小程序设计基线，没有无必要重写 WXML/WXSS。
- [ ] Full PRD 任务没有修改既有页面/组件样式基线；新增页面复用现有设计语言。
- [ ] 保留自定义 Tab、半屏弹窗、安全区适配。
- [ ] 保留关键手势：滑动删除、长按拖拽、周切换、弹窗开合。
- [ ] 接真实 API 的改动优先发生在 `services/` 或数据映射层。

## 5. 测试

- [ ] 有对应单元测试、接口测试或手动验收记录。
- [ ] 周计划生成规则有样例覆盖。
- [ ] 菜篮合并规则有样例覆盖。
- [ ] 关键页面完成冒烟。
- [ ] 无法运行的测试已说明原因和风险。

## 6. 文档

- [ ] 行为变更已同步模块 spec。
- [ ] API 变更已同步接口文档或任务卡。
- [ ] 验收标准变化已同步 checklist。
- [ ] 新增约束已同步 `AGENTS.md` 或 harness 文档。

## 7. Full PRD 额外检查

- [ ] 任务对应 `docs/tasks/full-prd-README.md` 中的任务 ID。
- [ ] 任务卡包含 `Full PRD 限制` 章节。
- [ ] 涉及生成能力时首版只启用 `provider=rules`，没有误接真实 AI。
- [ ] 涉及计划时日级计划仍是唯一事实源，周/月只聚合或批量写日级事实。
- [ ] 涉及前端时未修改既有样式、布局、手势、Tab、半屏弹窗和安全区适配。
- [ ] 涉及自助注销执行时包含 7 天可撤回期、最小完成记录、内部定时器令牌、幂等/重试和专用测试账号演练计划。
