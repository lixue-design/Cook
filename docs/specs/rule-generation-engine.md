# 规则生成引擎 Spec

## 1. 模块目标

所有原 PRD 中标记为 AI 的生成能力，首版统一使用可解释的本地/服务端规则生成；接口和数据结构预留 `provider` 抽象，后续可切换或并联 AI provider。

本模块覆盖：

- 菜谱草稿生成的规则 provider。
- 菜品图库匹配的规则 provider。
- 日/周/月计划生成的规则 provider。
- 用户习惯、三餐差异、营养均衡和计划联动规则。

## 2. 生成 provider 策略

### 2.1 首版 provider

```text
provider = rules
```

首版只实现 `rules` provider。所有生成结果必须可解释、可测试、可复现，不依赖模型服务。

### 2.2 预留 provider

```text
provider = ai
```

后续可以新增 `ai` provider，但不能改变前端主流程契约。切换方式建议：

- 配置级默认 provider。
- 用户级或实验级灰度 provider。
- 单次任务显式 provider。

无论 provider 是 `rules` 还是 `ai`，输出都必须经过同一套 schema 校验、用户确认和服务端最终校验。

## 3. 用户习惯模型

### 3.1 MVP 后新增的习惯字段

- 是否吃早餐：`hasBreakfast`
- 工作日早餐偏好：如快手、粥/面包/蛋奶。
- 午餐偏好：如便当、快手、少油。
- 晚餐偏好：如清淡、家庭共享、可多菜。
- 常用主食：米饭、面、馒头、杂粮等。
- 忌口/不喜欢食材。
- 常用人数。
- 工作日可接受耗时。
- 周末可接受耗时。

### 3.2 默认策略

用户未设置习惯时使用安全默认值：

- 默认吃早餐。
- 早餐优先 15 分钟以内或内置早餐组合。
- 工作日午/晚餐优先快手、营养均衡。
- 周末允许每天最多 1 道耗时菜。
- 不做复杂营养计算，只做食材角色和餐次结构均衡。

## 4. 三餐差异规则

### 4.1 早餐

- 优先早餐候选或内置早餐组合。
- 同一道早餐每周最多 2 次。
- 重复早餐至少间隔 2 天。
- 若用户设置不吃早餐，早餐餐段默认空，不自动填充。

### 4.2 午餐

- 工作日优先快手、可打包、主食明确。
- 尽量避免和前一日晚餐主食/主要蛋白连续重复。
- 可选择一餐完成类菜品，如炒饭、面、饺子。

### 4.3 晚餐

- 优先家庭共享，允许一荤一素一主食或两菜一主食。
- 晚餐和当日午餐尽量不重复主要食材。
- 晚餐可承接次日午餐的备餐偏好，但首版只做规则预留，不做复杂库存。

## 5. 营养均衡规则

首版采用可解释的轻量标签，不做营养素精算。

| 角色 | 识别依据 |
| --- | --- |
| 主食 | 菜名或食材含饭、面、粥、馒头、面包、饺子、馄饨、玉米等。 |
| 蛋白质 | 菜名或食材含肉、鱼、虾、蛋、豆腐、鸡、牛、猪等。 |
| 蔬菜 | 主料或菜名含青菜、白菜、生菜、豆角、西兰花、番茄、土豆等。 |
| 一餐完成 | 炒饭、盖饭、焖饭、面、饺子、馄饨、三明治等。 |
| 快手菜 | 耗时 < 45 分钟，或名称命中常见快手菜。 |
| 耗时菜 | 耗时 >= 45 分钟。 |

计划生成优先满足：

1. 每个正餐有主食来源。
2. 每天至少覆盖蛋白质和蔬菜。
3. 同一主要食材尽量不连续。
4. 一周内菜谱尽量多样。
5. 菜谱不足时按 warning 放宽规则。

## 6. 日/周/月计划联动

### 6.1 数据真相

`meal_plans` 和 `meal_plan_recipes` 仍是日级事实表。周计划和月计划都从日级事实聚合，不单独维护另一份可冲突的餐单真相。

```text
日计划事实表
  -> 周计划聚合视图
  -> 月计划聚合视图
```

### 6.2 写入规则

- 周计划生成：批量写入目标自然周的日级餐段。
- 月计划批量填充：按目标日期批量写入日级餐段。
- 日计划手动修改：直接更新日级事实，周/月视图自动反映。
- 月计划全局替换：本质是批量修改该月日级计划项。
- 历史复刻：复制历史日级快照到目标日期。

### 6.3 快照规则

- 所有生成、复刻、替换都写入菜谱快照。
- 后续菜谱编辑不污染已生成的日/周/月计划。
- 菜篮始终从计划快照同步。

## 7. 生成解释和 warnings

所有计划生成接口都应返回：

- `warnings[]`：菜谱不足、无早餐、无主食、无法一荤一素、用户习惯缺失等。
- `explanations[]`：可选，用于说明为什么选择某个菜。

示例：

```json
{
  "code": "NO_BREAKFAST_RECIPES",
  "message": "没有早餐菜谱，已使用内置早餐组合"
}
```

## 8. 验收标准

- 不配置任何 AI 模型时，链接/图片/文字入口和计划生成仍能走规则 provider 的可控流程。
- 周计划生成考虑早餐、午餐、晚餐差异。
- 生成结果体现主食、蛋白质、蔬菜的轻量均衡。
- 日计划修改后周/月计划聚合同步变化。
- 月计划批量操作最终写入日级事实表。
- 所有生成结果有稳定 warnings，可被页面展示。

## 9. 测试建议

- 单元测试：餐次标签、食材角色、用户习惯、重复控制、营养均衡评分。
- 接口测试：provider=`rules` 创建任务、周/月生成、用户隔离、warnings。
- 页面冒烟：习惯缺失、菜谱不足、日改周/月同步、月批量操作。
