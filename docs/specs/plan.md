# 计划模块 Spec

## 1. 模块目标

帮助用户把菜谱安排到每日三餐和一周餐单中，减少每天决定吃什么的成本。

## 2. MVP 范围

### 2.1 必做

- 日计划查看和编辑。
- 早餐、午餐、晚餐三餐分区。
- 添加菜谱到指定日期和餐段。
- 移除餐段菜谱。
- 周计划查看。
- 一键生成本周计划。
- 周计划和日计划联动。
- 计划菜谱快照。

### 2.2 暂不做

- 月计划。
- 月度复盘统计。
- 历史日计划一键复刻。
- 用户偏好、忌口、人数设置。
- AI 自动菜单。

## 3. 核心流程

### 3.1 生成周计划

```text
周计划页 -> 点击生成 -> 服务端按规则生成 -> 展示七天三餐 -> 用户调整
```

### 3.2 手动调整日计划

```text
日计划页 -> 选择餐段 -> 选择菜谱 -> 写入计划快照 -> 页面刷新
```

周计划页右下角新增入口先展示“AI 搞定一周菜单 / 我自己来安排”选择弹窗：选择 AI 生成当前周计划；选择手动安排后打开“选择日期与餐次”，确认餐次后进入选菜谱或写随手记的流程。

### 3.3 移除计划菜谱

```text
餐段菜谱卡片 -> 删除 -> 从该餐段移除 -> 不影响原菜谱
```

## 4. 页面/入口

| 页面/组件 | 职责 |
| --- | --- |
| 周计划页 | 周切换、七天三餐概览、进入日计划；右下角新增可选择自动生成或手动安排。 |
| 日计划页 | 日期切换、三餐分区、添加/移除菜谱、进入菜谱详情。 |
| 选择菜谱页/弹窗 | 从菜谱库选择菜谱加入计划。 |
| 计划生成确认弹窗 | 已有计划时提示是否覆盖。 |

## 5. API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/week-plans/{weekStartDate}` | 获取某周计划。 |
| POST | `/api/week-plans/generate` | 生成某周计划。 |
| PUT | `/api/week-plans/{weekStartDate}` | 保存整周计划。 |
| GET | `/api/day-plans/{date}` | 获取某日计划。 |
| PUT | `/api/day-plans/{date}` | 保存某日计划。 |
| POST | `/api/day-plans/{date}/meals/{mealType}/recipes` | 添加菜谱到餐段。 |
| DELETE | `/api/day-plans/{date}/meals/{mealType}/recipes/{planRecipeId}` | 移除餐段菜谱。 |

## 6. 数据模型

### meal_plans

关键字段：

- `id`
- `user_id`
- `date`
- `week_start_date`
- `meal_type`: `breakfast` / `lunch` / `dinner`
- `created_at`
- `updated_at`

唯一约束：

```text
unique(user_id, date, meal_type)
```

### meal_plan_recipes

关键字段：

- `meal_plan_id`
- `recipe_id`
- `recipe_snapshot`
- `sort_order`
- `source`: `generated` / `manual`

## 7. 业务规则

- 计划项写入时必须保存菜谱快照。
- 同一用户、同一天、同一餐次中的同一菜谱最多保存一条；前端重复触发或重试时服务端必须返回既有计划项，不能新增重复记录。
- 快照至少包含菜名、封面、耗时、热量、食材。
- 菜谱编辑不自动同步已生成计划。
- 菜谱删除不删除历史计划项。
- 日计划修改后，对应周计划视图必须同步。
- 计划页与菜篮页共享当前选择的自然周；日计划切换到另一周时，菜篮随之切换，菜篮切周后返回计划也展示同一周并尽量保留原来的星期几。
- 计划页首次进入默认展示周计划；用户切换到日计划或周计划后，需持久保存该选择，后续进入页面或重启小程序时恢复最后一次选择。
- 生成周计划时如已有计划，必须二次确认覆盖。
- 清空周计划必须一次性删除该周的计划记录及其菜品条目；清空成功后重新生成不得触发“已有计划”覆盖确认。页面在确认清空后立即展示空状态，失败时恢复服务端实际状态。
- 菜谱不足时允许生成不完整计划，并返回 warnings。
- 日计划与周计划加载中分别展示三餐分区骨架和周表格骨架；加载完成后再展示数据或失败态。

## 8. 周计划生成规则

- 候选菜谱优先使用服务端保存的 `system_tags`：早餐候选、主食、蛋白质菜、蔬菜菜、一餐完成及耗时等级；标签缺失时才使用兼容关键词规则。生成器不在小程序页面临时生成或修改标签。
- 早餐优先选择早餐候选，同一道早餐最多 2 次，至少间隔 2 天。系统只根据明确早餐分类或早餐菜式（如粥、包子、吐司、三明治）推断早餐；不根据鸡蛋、玉米等食材词单独推断，且带炒、炖、烧、汤等正餐烹饪语义的菜谱不推断为早餐，避免将番茄炒蛋、玉米排骨汤等正餐误排入早餐。
- 工作日午/晚餐优先一荤一素一主食，或一餐完成菜。
- 周末每天最多 1 道耗时菜。
- 同一道菜尽量不重复。
- 相同主要食材尽量不连续。
- 菜谱不足时逐步放宽重复规则。
- 无早餐菜谱时使用内置早餐补位项；组合中的食材分别保存为独立条目，例如「玉米、鸡蛋、牛奶」和「燕麦、牛奶」。
- 正餐的主食（含内置米饭）排在该餐段第一条，其后为荤菜、蔬菜。
- 无主食时使用「米饭」补位。
- 内置补位项以 `builtin: true` 快照保存，原菜谱 ID 为空；不会伪装成用户菜谱。
- 生成 warnings 使用稳定 code，至少覆盖菜谱不足、无早餐、无主食和无法组成一荤一素。

## 9. 错误态

| 场景 | 处理 |
| --- | --- |
| 菜谱不存在 | 添加失败并提示刷新。 |
| 已有周计划 | 生成前提示是否覆盖。 |
| 菜谱不足 | 生成成功但返回 warning。 |
| 日期非法 | 返回参数错误。 |
| 未登录 | 在当前页面弹出登录弹窗。 |

## 10. 验收标准

- 可查看某日早餐、午餐、晚餐。
- 可添加菜谱到指定日期和餐段。
- 可移除餐段菜谱。
- 可生成本周计划。
- 日计划修改后周计划同步展示。
- 删除原菜谱后计划快照仍可展示。
- 生成菜谱不足时有明确提示。

## 11. 测试建议

- 单元测试：周计划生成规则、主要食材识别、重复控制。
- 接口测试：添加、移除、生成、覆盖确认。
- 页面冒烟：周计划生成、日计划添加/删除、跳转菜谱详情。
