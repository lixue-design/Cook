# 菜篮模块 Spec

## 1. 模块目标

把日/周计划中的菜谱食材汇总成可执行的采购清单，支持用户勾选已采购食材。

## 2. MVP 范围

### 2.1 必做

- 按自然周查看周菜篮。
- 从日计划或周计划同步食材到菜篮。
- 同名、同单位且数字用量可解析的计划食材自动合并并相加；不做单位换算。
- 勾选/取消勾选采购项。
- 手动新增食材。
- 删除菜篮项。

### 2.2 暂不做

- 复杂单位换算。
- 按超市区域排序。
- 多人共享采购。
- 价格估算。
- 库存管理。

## 3. 核心流程

```text
周计划/日计划 -> 同步菜篮 -> 汇总食材 -> 菜篮页查看 -> 勾选采购
```

手动维护：

```text
菜篮页 -> 新增食材 -> 填写名称 -> 保存 -> 出现在未完成列表首位
```

手动新增支持用逗号分隔多项食材；每项末尾的“数字 + 常用单位”会拆为食材名称和用量，单位前后的空格不保留。例如输入“西红柿 2 个”保存为名称“西红柿”、用量“2个”；未填写可识别用量时仅保存名称。

## 4. 页面/入口

| 页面/组件 | 职责 |
| --- | --- |
| 周菜篮页 | 周切换、未完成/已完成列表、勾选、编辑、删除、清空、手动新增。 |
| 同步菜篮按钮 | 从计划触发食材同步。 |
| 菜篮项组件 | 展示名称、用量、来源、勾选状态。 |

## 5. API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/baskets/{weekStartDate}` | 获取某周菜篮。 |
| POST | `/api/baskets/{weekStartDate}/sync-from-plan` | 从计划同步菜篮。 |
| POST | `/api/baskets/{weekStartDate}/items` | 手动新增菜篮项。 |
| PATCH | `/api/baskets/{weekStartDate}/items/{itemId}` | 修改菜篮项或勾选状态。 |
| DELETE | `/api/baskets/{weekStartDate}/items/{itemId}` | 删除菜篮项。 |
| PUT | `/api/baskets/{weekStartDate}/items/check-all` | 批量勾选或取消。 |

## 6. 数据模型

### shopping_baskets

关键字段：

- `id`
- `user_id`
- `week_start_date`
- `status`
- `last_synced_at`
- `created_at`
- `updated_at`

唯一约束：

```text
unique(user_id, week_start_date)
```

### shopping_basket_items

关键字段：

- `basket_id`
- `name`
- `amount`
- `amount_text`
- `unit`
- `source`: `plan` / `manual`
- `source_refs`
- `checked`
- `sort_order`
- `pending_sort_order`：完成后恢复未完成列表的位置。
- `normalized_name`：用于名称精确合并的标准化键。

## 7. 食材合并规则

- 合并键对名称执行 NFKC、去除首尾空白、折叠连续空白、常见标点标准化和忽略大小写。
- 合并键为标准化名称、单位和可解析数字用量：同名同单位且两项用量均为数字时相加；同名食材中仅有一类可解析单位用量、其余未填写用量时合并展示为“无用量+500g”。同名食材仅有一类可解析单位用量且同时存在“少许”或“适量”时，数字用量合计后附加去重的定性用量，例如“盐2g + 盐3g + 盐少许 + 盐少许”展示为“盐5g+少许”。单位不同或其他已填写但不可解析的用量分别保留，不做单位换算。
- 合并结果汇总全部 `source_refs`，例如“来自番茄炒蛋・周一午餐”；来源快照同时保留菜谱名称、用时和热量，供菜篮页点击食材后展示来源菜谱清单。
- 手动重复新增不会创建新项：若原项已完成，则恢复为未完成并移动到未完成列表首位。
- 编辑后如与现有条目同名，按同一规则合并来源关系。
- 计划或菜谱来源被删除后，已生成的菜篮条目及其来源快照仍保留，不能被同步静默删除。
- 用户从计划页再次同步菜篮时，仍关联原菜谱的计划项使用原菜谱当前的食材；原菜谱已删除或无原菜谱的计划项回退使用计划快照。计划页展示内容始终使用其原有快照，不受此同步影响。
- 点击“食材来源”浮层内仍有关联菜谱的条目，进入该菜谱详情；没有关联菜谱的随手记或历史来源不可跳转。
- 菜篮食材仅在能解析出至少一个菜谱来源时才打开“食材来源”浮层；手动新增或无菜品来源的食材点击后不展示空弹层。

## 7.1 列表与维护规则

- 每周清单独立保存；切换周只读取目标自然周数据。
- 从菜谱详情「加菜篮」时，使用微信小程序原生 selector 选择周；选项为当前周起连续 9 周，食材写入所选周的菜篮。
- 与计划页共享当前选择的自然周；菜篮切周后，返回计划页时展示同一周。
- 未完成食材在前，已完成食材在后；新完成项置于已完成区首位。
- 已完成项恢复未完成时，优先恢复到此前的位置；位置无法使用时放到未完成区首位。
- 右滑仅显示删除；纵向滑动不得触发删除。
- 清空已购仅删除已完成项；清空全部需明确说明不会删除食谱或计划。
- 清空全部菜篮时，同时清除该周已生成的菜篮来源快照；之后从计划页再次加入时，只按当前计划重新生成食材。
- 菜篮加载中展示与勾选清单行结构一致的骨架图；加载完成后再展示数据、空态或失败态。
- 从计划页加入菜篮完成后，仅在计划页展示「已加入本周菜篮」Toast；即使本周没有可同步食材也不展示同步提示弹窗。

## 8. 错误态

| 场景 | 处理 |
| --- | --- |
| 当前周无计划 | 菜篮为空，提示先添加计划。 |
| 计划中菜谱无食材 | 跳过该菜谱，返回 warning。 |
| 同步失败 | 保留现有菜篮，不清空。 |
| 手动新增名称为空 | 阻止保存。 |
| 未登录 | 在当前页面弹出登录弹窗。 |

## 9. 验收标准

- 空菜篮展示空状态和新增入口。
- 有效名称新增到未完成列表首位；重复名称只保留一个条目。
- 勾选、恢复、编辑、右滑删除和两类清空符合上述列表规则。
- 周切换、来源展示、多来源保留及来源快照保留可用。

## 10. 测试建议

- 单元测试：名称标准化合并、来源关系、完成/恢复排序、手动重复新增。
- 接口测试：同步、勾选、编辑、新增、删除、清空。
- 页面冒烟：空态、周切换、来源、勾选采购、手动新增/编辑、右滑删除、两类清空。
