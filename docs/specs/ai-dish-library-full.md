# AI 菜品图库全量 Spec

## 1. 模块目标

建立可复用的标准菜品图库：同义菜名归一到标准菜品，命中存量图片则复用。首版未命中时返回占位或运营待补状态，不依赖 AI 生图；接口预留后续生成 provider。

## 2. 范围

### 2.1 必做

- 菜名清洗和标准化。
- 同义词映射维护。
- 标准菜品与图片资产绑定。
- 未命中图库时创建占位/运营待补记录。
- 预留后续 AI 生图任务接口。
- 图片优先级：用户手动上传图 > 标准图库图 > AI 生成图 > 默认占位图。
- 运营查看、替换、重新生成、下线图片。
- 生成成本、失败重试、内容安全和审计。

### 2.2 不做

- 不让未经审核的低质量图片强制覆盖用户手动图片。
- 不把图库运营能力混入普通用户小程序页面。
- 不在客户端保存模型密钥。

## 3. 核心流程

```text
用户输入菜名 -> 菜名标准化 -> 查同义词/标准图库
  -> 命中：返回标准图片
  -> 未命中：返回占位并创建运营待补记录
  -> 后续如启用生成 provider：生成完成后入库并进入可用/待审核状态
```

## 4. 数据模型建议

可复用现有 `dish_assets`、`dish_asset_keywords`、生成任务表，并补齐：

- 标准菜品表：`standard_dishes`
- 同义词表：`standard_dish_aliases`
- 运营审计表：`dish_asset_audit_logs`
- 图片质量状态：`pending_review` / `ready` / `rejected` / `retired`

## 5. API 契约建议

| REST 语义 | Action | 说明 |
| --- | --- | --- |
| `GET /api/dish-images/match` | `dishImages.match` | 根据菜名返回标准图片或生成状态。 |
| `POST /api/dish-images/generate` | `dishImages.generate` | 为标准菜名创建生成任务；首版返回待补记录。 |
| `GET /api/admin/dish-images` | `admin.dishImages.list` | 运营查看图库。 |
| `PATCH /api/admin/dish-images/{id}` | `admin.dishImages.update` | 替换、下线、改状态。 |
| `POST /api/admin/dish-aliases` | `admin.dishAliases.create` | 维护同义词。 |

## 6. 业务规则

- 菜名清洗只做可解释规则和可审计映射。
- 同义词变更必须记录操作者和时间。
- 未命中图库不能阻塞菜谱保存。
- 首版不调用 AI 生图，不能向用户承诺立即生成。
- 用户手动上传图只作用于个人菜谱，不自动进入全局图库。
- 后续如启用 AI 生图，必须有成本上限和失败兜底。
- 运营后台需要管理员鉴权，普通用户不可访问。

## 7. 验收标准

- 番茄炒蛋/西红柿炒鸡蛋等同义词可命中同一标准图。
- 未命中菜名可创建待补记录，失败不影响菜谱保存。
- 运营可替换或下线图片。
- 用户手动图不会被图库图覆盖。
- 全链路无模型密钥泄露。

## 8. 测试建议

- 单元测试：菜名清洗、同义词命中、优先级选择。
- 接口测试：图库匹配、生图任务、运营权限。
- 页面冒烟：编辑页自动匹配、手动替换、失败兜底。
