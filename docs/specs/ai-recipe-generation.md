# 菜谱生成 Spec

## 1. 模块目标

让用户可以通过受限的小红书公开链接、菜谱图片或文字描述生成可编辑菜谱草稿，降低手动录入成本。链接服务端仅提取公开页面声明的标题和正文摘要，再使用个人版 AI 环境中的 `hy3` 结构化；文字生成使用同一 AI；文字菜谱图片先经 OCR 提取文字，再由 `hy3` 结构化。生成结果必须先进入草稿，由用户确认后才保存为正式菜谱。

## 2. 范围

### 2.1 必做

- 链接生成菜谱。
- 图片生成菜谱。
- 文字生成菜谱。
- 统一生成任务模型。
- 链接入口仅支持小红书公开 HTTPS 链接；服务端仅提取标题和正文摘要，不下载图片、视频或评论，不读取账号数据。
- 文字入口调用独立的 AI 云函数，使用个人版环境的 `hy3`。
- 图片入口上传一张临时图片至个人版 AI 环境，调用通用印刷体 OCR 后复用 `hy3` 生成草稿；完成后删除临时图片。
- 生成结果回填菜谱编辑页草稿。
- 失败后保留用户输入，可切回手动录入。
- provider 抽象、超时、重试、requestId 和可诊断错误。
- 服务端最终校验生成结果，不信任任一 provider 输出。

### 2.2 不做

- 不让生成 provider 直接创建正式菜谱。
- 不把未审核输出直接写入全局图库。
- 不把模型密钥放在小程序端。
- 不承诺小红书公开链接 100% 可解析。
- 不抓取需要登录、验证码或额外访问权限的内容，不绕过平台限制。
- 不把成长计划的 AI 调用改为体验版业务数据迁移。

## 3. 核心流程

### 3.1 链接生成

```text
新增弹窗 -> 链接生成 -> 粘贴链接 -> 创建解析任务 -> 生成草稿 -> 编辑页确认 -> 保存菜谱
```

### 3.2 图片生成

```text
新增弹窗 -> 图片生成 -> 拍照/相册 -> 上传图片 -> 创建识别任务 -> 生成草稿 -> 编辑页确认 -> 保存菜谱
```

### 3.3 文字生成

```text
新增弹窗 -> 文字生成 -> 输入描述 -> 个人版 AI 云函数生成并校验草稿 -> 编辑页确认 -> 保存菜谱
```

## 4. API 契约建议

当前仓库使用 Cloud Function action 模式。REST 语义可映射为 action。

| REST 语义 | Action | 说明 |
| --- | --- | --- |
| `POST /api/generation/recipe-jobs` | `generation.recipeJobs.create` | 创建链接/图片/文字生成任务。 |
| `GET /api/generation/recipe-jobs/{jobId}` | `generation.recipeJobs.get` | 查询任务状态和生成结果。 |
| `POST /api/generation/recipe-jobs/{jobId}/cancel` | `generation.recipeJobs.cancel` | 取消未完成任务。 |

`POST /api/generation/recipe-jobs`

```json
{
  "sourceType": "link",
  "provider": "rules",
  "input": {
    "url": "https://example.com/recipe"
  }
}
```

`sourceType` 可选：

- `link`
- `image`
- `text`

链接入口、文字入口和图片入口均使用 `ai`；链接入口先受限地提取公开标题/正文，图片入口额外使用 OCR。

## 5. 数据模型建议

### recipe_generation_jobs

- `id`
- `user_id`
- `source_type`: `link` / `image` / `text`
- `provider`: `rules` / `ai`
- `input_payload`
- `status`: `pending` / `running` / `succeeded` / `failed` / `cancelled`
- `result_draft`
- `error_code`
- `error_message`
- `request_id`
- `cost_units`
- `created_at`
- `updated_at`
- `completed_at`

## 6. 结果草稿格式

生成结果必须适配现有菜谱编辑页字段：

- `title`
- `categoryId`
- `coverUrl`
- `duration`
- `calories`
- `ingredients`
- `steps`
- `sourceType`
- `sourceMeta`

## 7. 业务规则

- 任务必须属于当前登录用户。
- 链接内容解析、OCR 图片文字读取和文字拆分均在服务端执行。
- 链接仅允许 `xiaohongshu.com`、`xhslink.com`、`xhslink.cn` 及其子域名的 HTTPS 地址；支持直接粘贴小红书分享文案，服务端仅提取其中第一个有效小红书链接。禁止用户名、密码、端口及跳转至非白名单域名，以避免服务端请求伪造。
- 链接请求最多 4 次跳转、8 秒超时、512KB 响应；仅读取页面公开声明的标题与描述，提取后最多传入 5,000 字给 AI，且不记录完整链接页面内容。
- AI 云函数限制输入至 5,000 字，校验模型返回 JSON、字段长度和制作步骤；不得记录完整输入或完整输出日志。
- 文字生成默认使用规范菜名；分类仅可输出“爽口凉菜、家常小炒、大口吃肉、一碗鲜汤、饱腹主食”，不确定时留空；食材以“名称用量”格式用顿号分隔。
- provider 输出必须经过 schema 校验、长度校验和食材/步骤清洗。
- 图片生成仅支持以文字为主的菜谱截图；使用通用印刷体 OCR 提取文字，未识别到文字时提示用户改用清晰截图或手动填写。临时图片只用于本次识别，完成后删除。
- 菜名为空时不能生成成功态。
- 食材无法解析数字用量时保留原始文本，不丢弃。
- 步骤最多 100 条，单条最多 500 字。
- 生成草稿保存失败时保留用户原始输入。
- 生成任务失败不能阻塞手动录入。
- 文字生成进入编辑页后，如未保存即返回，必须回到保留原文本的文字输入页；再次确认时必须以当前文本重新生成草稿，不能复用上一次结果。

## 8. 错误态

| 场景 | 处理 |
| --- | --- |
| 链接格式错误或非小红书链接 | 返回 `LINK_INVALID_URL` / `LINK_NOT_SUPPORTED`，提示更换链接或手动录入，保留已粘贴内容。 |
| 外链不可访问、超时或页面未提供标题/正文 | 返回稳定的 `LINK_*` 错误，提示复制正文或上传截图，允许重试。 |
| 非菜谱内容 | 仍生成可编辑草稿，由用户确认或改为手动录入。 |
| 图片格式/大小非法 | 前端和后端均拦截。 |
| 图片中未识别到文字 / OCR 失败 | 提示更换清晰截图或切回手动录入。 |
| 文字为空 | 阻止创建任务。 |
| provider 超时 | 返回 `GENERATION_TIMEOUT`，可重试或手动录入。 |
| 内容安全失败 | 返回安全提示，不展示敏感生成内容。 |

## 9. 验收标准

- 受支持的链接、文字入口均能生成可编辑草稿；文字菜谱截图经 OCR 后能生成可编辑草稿。
- 页面访问受限或页面未提供标题/正文时，链接入口给出可理解的失败提示并保留输入，可切换文字或图片导入。
- 生成失败不清空用户输入。
- 生成草稿保存后进入菜谱详情。
- provider 输出非法时服务端拦截。
- 任务状态可诊断，错误带稳定 code 和 requestId。
- 小程序端不包含模型密钥。

## 10. 测试建议

- 单元测试：schema 校验、输出清洗、错误 code 映射。
- 接口测试：创建任务、查询任务、失败态、用户隔离。
- 页面冒烟：三种入口、生成中、失败、成功回填、保存。
