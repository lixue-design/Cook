# 菜谱模块 Spec

## 1. 模块目标

让用户可以管理自己的菜谱库，并为计划和菜篮提供稳定的数据来源。

## 2. MVP 范围

> 当前实现状态：`pages/recipe-create` 已按编辑页设计稿恢复；表单使用一个连续的「食材」输入区，旧数据的主料、辅料、调料在进入编辑页时会合并到该字段。菜名与食材均使用原生 placeholder，避免输入法组合文本与自定义覆盖提示层发生冲突。

### 2.1 必做

- 菜谱分类列表、新增、编辑、删除、排序。
- 菜谱列表按分类展示。
- 菜谱详情展示封面、名称、耗时、热量、食材、步骤。
- 手动新建菜谱。
- 编辑菜谱。
- 删除菜谱。
- 菜谱封面上传。
- 新建与编辑草稿按菜谱 ID 隔离保存在本地，保存成功后清除；从「手动填写」进入时始终创建新菜谱，不恢复此前的新建草稿。
- 封面和步骤图在写入表单前先保存为小程序本地持久文件；真实服务保存时再上传，临时文件失效不得导致详情页无图。若远端步骤图存储不可用，保存前明确提示并按无图步骤保存，文字内容不能丢失。
- 菜谱详情加入计划、加入菜篮入口。

### 2.2 创建方式边界

- 菜谱列表右下角「+」先打开新增菜谱弹窗，提供链接导入、图片生成、文字生成和手动填写四种入口。
- 链接入口当前仅支持小红书公开 HTTPS 链接：服务端仅读取页面公开声明的标题和正文摘要，再调用 AI 生成可编辑草稿；文字入口调用 AI；图片入口对文字菜谱截图使用 OCR 提取文字后调用 AI，均先进入可编辑草稿。

### 2.3 暂不做

- 非小红书平台链接解析、需要登录或绕过访问限制的链接解析。
- 社交分享。
- 多端协同编辑。
- 复杂营养分析。

## 3. 核心流程

### 3.1 新建菜谱

```text
菜谱列表 -> 点击右下角 + -> 选择链接导入 / 图片生成 / 文字生成 / 手动填写 -> 进入可编辑表单 -> 保存 -> 菜谱详情
```

### 3.2 编辑菜谱

```text
菜谱详情 -> 编辑 -> 回填表单 -> 保存 -> 返回详情并刷新
```

### 3.3 删除菜谱

```text
菜谱详情 -> 更多 -> 删除 -> 二次确认 -> 软删除 -> 返回列表
```

已进入计划的菜谱删除后，计划继续展示快照。

## 4. 页面/入口

| 页面/组件 | 职责 |
| --- | --- |
| 菜谱列表页 | 分类栏、菜谱卡片、分页加载、新建入口。 |
| 分类管理弹窗/页 | 分类增删改排。 |
| 菜谱详情页 | 展示完整菜谱，提供编辑、删除、加入计划、加入菜篮。 |
| 新建/编辑菜谱页 | 表单录入、图片选择、食材编辑、步骤编辑、保存。 |
| 选择菜谱页 | 给计划选择菜谱。 |

## 5. API 契约

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/recipe-categories` | 获取分类列表。 |
| POST | `/api/recipe-categories` | 创建分类。 |
| PATCH | `/api/recipe-categories/{categoryId}` | 重命名分类。 |
| DELETE | `/api/recipe-categories/{categoryId}` | 删除分类，菜谱归入未分类。 |
| PUT | `/api/recipe-categories/sort` | 更新分类排序。 |
| GET | `/api/recipes` | 分页获取菜谱。 |
| POST | `/api/recipes` | 创建菜谱。 |
| GET | `/api/recipes/{recipeId}` | 获取菜谱详情。 |
| PUT | `/api/recipes/{recipeId}` | 更新菜谱。 |
| DELETE | `/api/recipes/{recipeId}` | 删除菜谱。 |
| POST | `/api/uploads/recipe-image` | 上传菜谱图片。 |

## 6. 数据模型

### recipes

关键字段：

- `id`
- `user_id`
- `category_id`
- `name`
- `cover_image_url`
- `cook_time_minutes`
- `calories_kcal`
- `source_type`
- `status`
- `created_at`
- `updated_at`
- `deleted_at`
- `system_tags`：服务端根据菜名、食材、步骤、分类和耗时派生的系统标签；仅供计划生成使用，不由用户编辑。

### recipe_ingredients

关键字段：

- `recipe_id`
- `group_type`: `main` / `side` / `seasoning`
- `name`
- `amount`
- `amount_text`
- `unit`
- `sort_order`

### recipe_steps

关键字段：

- `recipe_id`
- `description`
- `image_url`
- `sort_order`

## 7. 业务规则

- 菜品名称必填，最多 12 个字；输入框使用微信原生 `maxlength`，前端与服务端均做最终校验。
- 分类名称最多 8 个字符；未选择分类时归入「未分类」。
- 系统默认分类依次为「爽口凉菜、家常小炒、大口吃肉、一碗鲜汤、饱腹主食」；用户可在分类管理中维护分类。
- `mock` 模式仅为可用性测试预置上述五个默认分类，每类 3 道菜谱（共 15 道）；它们与新建菜谱共用同一菜谱数据源。每道测试菜使用对应的本地 1:1 成菜封面，并提供至少三步可跟做的文字步骤。真实接口模式不会写入这些测试数据。
- 新建/编辑菜谱时，分类选择使用微信小程序原生 selector，选项为当前可用分类。
- 耗时为 1-999 正整数，可为空。
- 热量为 1-9999 正整数，可为空。
- 新建/编辑页将所有食材录入同一个不分类的文本框；旧数据的主料、辅料、调料进入编辑页时合并为该文本。详情页同样按原有顺序合并为一个「食材准备」文本区展示。
- 用户上传封面时，服务端保留原图并同步生成 480×480 WebP 列表缩略图（质量 78、居中智能裁切）。菜谱列表、搜索结果、日计划和菜篮来源清单统一加载缩略图；菜谱详情仅加载原图。缩略图生成或写入失败时，封面按旧路径安全回退原图；旧菜谱在用户重新上传封面前也继续使用原图。关联菜谱存在时始终读取当前菜谱数据，更新后通过菜谱数据版本刷新全部列表；没有封面时统一展示封面占位图。菜谱列表接口只返回卡片所需的 ID、标题、封面、耗时、热量和裁切信息，不返回食材和步骤；列表首屏按分类最多加载 20 道，滚动到某分类底部时再自动追加下一页，每页 20 道、服务端上限 50 道。搜索、计划选菜和菜篮来源清单仍读取完整当前目录，不能因列表分页遗漏菜谱。列表与搜索封面均使用微信原生图片懒加载。历史计划与菜篮仍仅保留原食材快照作为业务数据回退。
- 制作步骤最多 100 条，单条文字最多 500 个字符。
- 步骤按 `sort_order` 连续展示，删除后重排。
- 编辑页当前不包含自定义键盘工具栏、键盘高度监听、焦点跳转或键盘专用滚动避让逻辑。菜名、食材和步骤均使用微信原生 `placeholder`；所有提示语颜色统一为 `#B0B6C3`，其中食材仅通过原生 `placeholder-class` 统一提示语的颜色与文字规格，不使用覆盖层。`input` 与 `blur` 事件同步表单值，确保拼音组合文本在切换输入框时不会丢失。食材与步骤 textarea 关闭微信原生确认栏，并关闭 textarea 默认内边距。菜品名称的提示语与已输入文字均为 Regular（字重 400）；食材提示语、食材已输入文字和步骤已输入文字均为 14px、行高 24px，食材默认至少两行并随内容向下增长。已填写文字或添加图片的步骤可左滑打开右侧贴边的红色「移除」操作，按钮随步骤内容高度撑满；点击后立即删除该步骤；同一时刻最多展开一条。后续新增编辑交互前，须以独立验收清单在 iOS 和 Android 真机完成验证。
- 表单变更后退出需二次确认；退出或保存失败时保留本地草稿，临时图片路径不写入可恢复草稿。
- 删除分类时，分类下菜谱进入「未分类」。
- 删除菜谱必须软删除，避免历史计划无法引用。
- 菜谱保存成功后刷新列表、详情、计划选择器数据。
- 创建或编辑菜谱时，服务端必须同步重建并写入 `system_tags`；客户端不得提交或覆盖该字段。标签记录 `value`、`source`、`confidence` 和 `tagVersion`，其中来源仅可为 `title`、`title_alias`、`ingredients`、`steps`、`category`、`duration`、`default_rule`。
- 系统标签当前覆盖餐段候选、菜品角色、蛋白质类别、蔬菜类别、烹饪方式、耗时等级和一餐完成标识。示例：「西红柿炒鸡蛋」写入 `tomato`（`title_alias` / 高可信度）与 `egg`（`title` / 高可信度）；无法从菜名判断午晚餐时，以低可信度的 `default_rule` 补为午餐、晚餐候选。
- 已有菜谱在系统标签迁移时一次性回填；周计划生成仅读取已持久化的标签。标签缺失或版本无法识别时，生成器才使用兼容的旧关键词规则，不阻塞生成。
- 菜谱列表加载中展示与分类栏、菜谱卡片结构一致的骨架图；加载完成后再展示数据、空态或失败态。

## 8. 错误态

| 场景 | 处理 |
| --- | --- |
| 名称为空 | 阻止保存，提示「请输入菜品名称」。 |
| 耗时/热量非法 | 阻止保存，提示合法范围。 |
| 保存失败或退出编辑 | 保留当前输入和隔离的本地草稿；再次进入恢复。 |
| 封面上传失败 | 允许重试；可选择无图保存，表单内容不能丢失。 |
| 步骤图无法持久化 | 保存前提示无图保存步骤，保留步骤文字。 |
| 分类不存在 | 保存时默认归入未分类。 |
| 菜谱不存在或已删除 | 详情页展示不可用提示并提供返回。 |

## 9. 验收标准

- 可创建完整菜谱并在列表、详情中展示。
- 可编辑菜谱并刷新详情。
- 可删除菜谱，列表不再展示。
- 删除菜谱后，已有计划中的快照仍可展示。
- 分类可增删改排，删除分类不删除菜谱。
- 封面上传失败不会导致表单内容丢失，并可无图保存。
- 步骤图远端持久化不可用时，用户确认后可无图保存步骤文字。
- 新建草稿、不同菜谱的编辑草稿互不污染，保存成功后对应草稿被清除。
- 退出未保存表单时有二次确认。

## 10. 测试建议

- 单元测试：字段校验、食材解析、步骤重排。
- 接口测试：创建、更新、删除、分页查询、分类删除。
- 页面冒烟：新建菜谱、编辑菜谱、删除菜谱、分类管理。
