# Agent 操作指南

本文面向 Codex/Agent，也适用于人类研发接手任务时自检。

## 1. 开工前

先回答四个问题：

1. 任务属于哪个模块：菜谱、计划、菜篮、登录、合规、基础工程还是 AI 图库。
2. 是否属于 MVP 范围。
3. 需要读取哪些最小上下文。
4. 完成后如何验证。

若任务没有明确验收标准，先补任务卡或在回复中列出假设。

## 2. 上下文读取规则

只读必要上下文，避免把整个仓库都塞进工作记忆：

- 菜谱任务：读 `docs/specs/recipe.md`。
- 计划任务：读 `docs/specs/plan.md`。
- 菜篮任务：读 `docs/specs/basket.md`。
- 跨模块任务：读相关模块 spec 和 MVP 范围。
- AI 图库任务：若 `docs/ai-dish-library/README.md` 已建立则额外读取；若尚未建立，先执行 `docs/tasks/TASK-AI-DISH-001.md` 明确专项边界。

如发现代码与 spec 不一致，优先指出差异，再决定是修代码还是更新 spec。

## 3. 实现约束

- 一次任务只完成一个可验证目标。
- 不把 mock 数据伪装成真实持久化能力。
- 不新增生产依赖，除非任务明确需要且说明理由。
- 不绕过登录态和用户隔离。
- 不让前端成为唯一业务规则来源。
- 不破坏已有页面交互，尤其是菜谱列表、计划页、菜篮页主路径。

## 4. 验证要求

按风险选择验证层级：

| 改动类型 | 最低验证 |
| --- | --- |
| 纯文档 | 检查链接和结构。 |
| 工具函数 | 单元测试。 |
| 接口 | 单元测试或接口测试，覆盖错误态。 |
| 数据库迁移 | migration up/down 或等价 SQL 检查。 |
| 小程序页面 | 页面主流程手动冒烟。 |
| 计划/菜篮规则 | 单元测试 + 手动样例。 |

不能运行测试时，必须说明：

- 未运行的命令。
- 未运行原因。
- 已做的替代检查。
- 剩余风险。

## 5. 汇报格式

任务完成后用短格式汇报：

```text
完成：
- 改了什么
- 覆盖哪些验收点

验证：
- 跑了哪些命令或手动检查

风险/后续：
- 未覆盖事项或建议下一步
```

## 6. 常见禁止事项

- 不在未确认范围时实现 AI 生成菜谱。
- 不把月计划塞进周计划任务。
- 不在菜篮里做复杂单位换算。
- 不删除用户或他人已有改动。
- 不把临时调试地址、密钥、token 提交到代码。
